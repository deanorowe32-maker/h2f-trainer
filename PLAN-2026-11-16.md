# Plan: clearer screens and a working data safety net

## Primary goal
A Soldier opening the app sees today's exercises first, reads every label without a legend, and never loses their logged data if the phone clears the browser's main storage.

Sources: `DESIGN-IS-2026-11-16/` (Rams audit, 16/30, REDESIGN of the UI layer) and `PATHFINDER-2026-11-16/` (duplication report). Execution rule (ponytail): smallest change that works, reuse existing functions and CSS, no new abstractions.

## Phase 0: Discovery (done)
**How this serves the primary goal:** pins every change to code that exists, so nothing is invented.

No external APIs are involved; the "allowed APIs" are the app's own functions and the browser's IndexedDB:
- `save()` index.html:1303; `idbOpen` declared at :1308 (state) and :4109 (photos); `idbPut` :1311, `idbRestore` :1312; photo users `phInit…phDeleteAll` :4110–4137.
- Date keys: `dayKeyTs` :1427, `today` :2257, `rbDK` :2307, `slKey` :3038; `monday` :1327.
- Labels: `DTYPES` :1235, `DSHORT` :1508, `schedHtml` :1434, `strip` :1472, code span in `itemRow` :1482 (CSS `.nm .code` :195), "%" box in `itemRow`, `.jump` chip rows CSS :762.
- Train layout: `viewTrain` :1535, title/subtitle :1537–1538, focus chips, "How this works", format chips :1541–1544.
- Readiness band label: `vzBars` band span :2945, CSS `.vz-band`.
- Header subtitle: index.html:907 `<div class="sub">Holistic Health &amp; Fitness`.
- CSS font sizes (lines 1–897): 27 distinct px values from 10 to 78.
Anti-patterns: no new storage layer, no CSS framework, no feature flags, no data migration.
