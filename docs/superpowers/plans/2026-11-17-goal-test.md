# My Goal Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a Soldier build a personal goal test, present it to a leader, log retests and track progress, under Train → Test.

**Architecture:** All code in `index.html` (single-file PWA), next to the CFT practice code (`cftHtml`, `cftAct`). State in `S.goal`, saved with `save()` and included in backups (`BK_KEYS`, `cleanBackup`, `applyBackup`). Sharing reuses the base64url pattern of `xsEnc`/`xsDec` with a `#gt=` link hash.

**Tech Stack:** Plain HTML/CSS/JS, no build step; Playwright (Python) for the check script.

**Spec:** `docs/superpowers/specs/2026-11-17-goal-test-design.md`

## Global Constraints
- 1–6 events; measures: `reps`, `time` (m:ss, lower is better), `weight` (app unit via `au()`), `distance` (`mi` or `km`).
- One active test (`S.goal.cur`), older ones in `S.goal.past` (max 20).
- Copy: the summary is headed "Personal training goal"; approval line reads "Approved by <name>, <date>" and is the Soldier's own entry. No Army form look, no seals.
- Bump the `sw.js` cache version string; commit to `main`.

## Review Focus
1. Time typed as "8:30", "8.5" or "510" → stored as seconds (510); "8:3x" → rejected with the field marked invalid, test not saved.
2. Goal "worse" than baseline (e.g. time goal slower than baseline) → still allowed but progress bar clamps 0–100% and "met" uses direction (lower-is-better for time).
3. A shared link opened on a phone that already has its own goal test → shows the shared one read-only with "Make this my goal test", never overwrites silently.
4. Retest with some events skipped → progress uses each event's latest logged value; skipped events keep their previous value.
5. Restoring a backup with a malformed `goal` object → ignored field by field, app still loads.
